# Settings sync

## What it does

Export Settings… / Import Settings… move all settings to another Mac in one `.pcsettings` file (JSON, `kind` `photocraft-settings`, `version` 1): two icons at the top right of Preferences, and engine commands `edit.preferences.exportSettings` / `edit.preferences.importSettings` (Edit ▸ Preferences; `{path}` or `{text}`, `dryRun`). Parts: Preferences (every section, Top Bar items, History Options, Layer Mask Display Options), Color Settings, Keyboard Shortcuts (the shortcuts backup with chords and When, saved sets), Menus, Toolbar, Context Menus, Workspaces and Panels (saved layouts, lock, live layout, no screen positions), tool options and view settings, spelling dictionary. Left out: recent files, folders and files of one Mac (LUT folder, log file, plug-in folder, scratch disks, profile paths, monitor profile), graphics and memory limits (adapter, backend, GPU memory, Memory Usage, tile size), the current tool and brush, last dialog choices, recent colors, script events, and the preset libraries (gradients, styles, shapes, patterns, swatches, tool presets, export and document presets: libraries, moved by Edit ▸ Presets ▸ Export/Import Presets). A file is checked whole first: a bad value for a setting this build knows is a short error and nothing changes. A setting, section or part this build does not have is skipped and named, in a file of any version, so a file from a newer PhotoCraft imports everything this build understands; a part or key the file lacks stays. The prompt names what is replaced and, in one calm line, the skipped settings (the first five, then "and N more"; the full list on hover). The command's reply (`dryRun` too) has `unknown` (the names, at most 200) and `unknownCount` next to `skipped` (other notes). OK applies in one step and saves. Options bar: the brush size under the brush preview stays inside its box (upstream has the same lines)

**Sync folder** (`feat/settings-sync-folder`; native only: on the web the row and the two commands are absent, and the `sync` preference stays as data). Preferences has a Sync Folder row under the search field: the chosen folder's path, Choose…, Save to Folder, Load from Folder and a Keep in Sync checkbox (Save, Load and Keep in Sync wait for a folder). Commands `edit.preferences.saveSettingsToFolder` and `edit.preferences.loadSettingsFromFolder` (`dryRun`); both use the preference `sync.folder` and take no path. Called by a person without parameters, Save writes what the Preferences window shows and Load opens the Import prompt, which also says "Saved on <Mac>, <time>"; with parameters, or from an agent, the engine does the work. Both are in Edit ▸ Preferences after Import Settings….
- **The file** is `photocraft.pcsettings` in the folder, the usual settings file plus a top-level `savedBy`: `{"computer": "<the Mac's computer name, as Sharing shows it>", "at": "<RFC 3339 with the Mac's offset, to the second, e.g. 2026-11-02T14:30:05+01:00>"}`. `savedBy` is a note about the file, not a setting: a missing or unreadable one is ignored (the prompt just leaves the line out), never a reason to refuse. Other ArtCraft apps keep their own file there (`lightcraft.lcsettings`); only `photocraft.pcsettings` is ever read or written. The file is staged under a hidden name in the same folder (`.photocraft.pcsettings.<pid>-<n>.tmp`) and renamed over the old one (no step where the file is missing), the temporary file goes on any failure, and the old file stays whole. An older build that has the unknown-settings rule skips `savedBy` and names it in the prompt; the first build (before PR #2) refuses a file with it ("“savedBy”: not a part of a settings file"), nothing changed.
- **The shared choice**: choosing a folder also writes `~/Library/Application Support/ArtCraft/sync-folder.json`, `{"path": "<folder>"}`, atomically; other keys already in it are kept, a missing or damaged file is replaced. A Mac with no folder chosen shows that folder (read once when Preferences opens; ignored unless it is an absolute path) with a Use This Folder button.
- **Keep in Sync** (built; it was simple): on quit it saves to the folder, unless the folder's file comes from another Mac and is newer than the last one this Mac saved or loaded (saving would replace it unseen). At start it offers such a file as the Load prompt. "Another Mac" means a different computer name; "newer" compares `savedBy.at` as points in time against `sync.last`, the `at` of the last file this Mac saved or loaded (empty: any file from another Mac is offered). Cancel on the prompt asks again at the next start. A folder that is gone shows a message in the status bar at start and is logged on quit.
- **`sync.*` preferences** (`folder`, `keep`, `last`) are this Mac's: not in the file, listed in `NOT_IN_FILE`, and a file carrying a `sync` section skips it and names it. `prefs.set` on `sync` is refused for agents (`automation_rejects_ambient_path`), so an agent cannot point the commands at another folder.
- **Errors** (a short message, nothing changed): no folder chosen, the folder gone, a file where the folder should be, a read-only folder or no permission, a full disk, no file in the folder yet, a file iCloud has not downloaded yet (`.photocraft.pcsettings.icloud`), a file too big or not text.

## Own files

engine `prefs/settings_sync.rs` + `settings_sync/tests.rs`, `prefs/settings_folder.rs` (`SyncPrefs`, every target) + `settings_folder/native.rs` + `settings_folder/tests.rs` (the folder, file, clock and commands, not on wasm); ui-egui `prefs/prefs_ui/settings_sync.rs` + `settings_sync_tests.rs`, `prefs/prefs_ui/settings_folder.rs` + `settings_folder_tests.rs`, `panels/brush_size_label_tests.rs`

## Hooks in official files

engine `Cargo.toml` (`chrono` with `clock`, for the Mac's time zone), `lib.rs` (`Session::settings_checks`, `Session::sync_env`, not on wasm), `prefs.rs` (`mod settings_sync`, `mod settings_folder`, the field `sync`), `prefs/cmds.rs` (two specs added, then two more, not on wasm), `shortcut_sets.rs` (`validate` is `pub(crate)`); automation `workspace.rs` (+ test: the two commands with `path` are refused for agents; `sync.*` in `prefs.set` is refused, the two folder commands are allowed); ui-egui `app.rs` (the offer at start, the save on quit), `prefs/prefs_ui.rs` (mods, two re-exports), `prefs_ui/dialogs.rs` (route, OK on the prompt), `prefs_ui/fields.rs` (icons beside the search field, the Sync Folder row, prompt body), `dialogs.rs` (OK reads Import), `menus/items.rs` (menu order, four items), `panels.rs` (test mod), `panels/brush_controls.rs` (brush size text 2 pt higher, preview 1 pt higher)
